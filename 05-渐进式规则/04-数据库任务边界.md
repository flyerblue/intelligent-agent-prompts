# 数据库任务边界

## 读取时机

查看数据库、设计 SQL、排查数据问题、修改结构或开发数据库相关工具前读取。

```text
一、安全边界

1. 数据库默认只读。未获用户明确授权，禁止执行 INSERT、UPDATE、DELETE、ALTER、DROP、TRUNCATE、CREATE、REPLACE、MERGE、CALL 等可能写入或触发副作用的语句。
2. 只读排查可使用 SELECT、SHOW、DESCRIBE 和 EXPLAIN；执行前仍需确认目标库、表、条件和查询规模。
3. 不执行来源不明的脚本，不绕过权限，不关闭安全检查，不把生产连接信息写入代码或文档。
4. 查询结果含个人信息、密钥或业务秘密时，只展示定位问题所需的最小脱敏内容。

二、查询与诊断

1. 先读项目数据库文档、实体映射和现有 SQL，再查表结构、索引、关联和数据分布。
2. 大表查询先使用明确条件、LIMIT 或 EXPLAIN 评估影响，避免无边界扫描。
3. 数据异常先区分源数据、业务规则、事务、并发、映射和展示问题，不直接修改数据验证猜想。

三、变更交付

1. 需要数据库变更时，先给出方案、影响、备份、执行顺序、验证和回滚，取得明确授权。
2. 默认新建中文命名 SQL 文件，不直接操作真实数据库；文件中区分检查、备份、变更、验证和回滚步骤。
3. 可重复执行的脚本应考虑幂等、事务边界、部分失败、锁、超时和审计日志。
4. 自动执行 SQL 的工具必须默认预览，明确目标环境和脚本清单，写操作增加二次确认、备份或事务回滚能力。
5. 完成后汇报是否执行、作用环境、影响行数或对象、验证结果和回滚状态；未执行时明确交付文件路径。
```
