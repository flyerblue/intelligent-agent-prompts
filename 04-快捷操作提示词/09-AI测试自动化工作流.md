# AI 测试自动化工作流

## 操作目标

完成“理解验收标准、设计用例、生成或审查脚本、执行验证、定位失败、修复并回归”的测试闭环。

## 提示词正文

```text
执行“AI 测试自动化工作流”。先完整读取：

1. D:\1poj\学习\智能体提示词体系\02-主场景提示词\08-测试与验证.md
2. D:\1poj\学习\智能体提示词体系\05-渐进式规则\03-测试执行边界.md

一、选择测试子场景

1. 新功能测试：界面或接口未稳定时先输出验收用例和自动化设计，不强行生成最终脚本。
2. 既有功能回归：优先复用和改造现有测试，处理脆弱选择器、固定等待、脏数据和共享状态。
3. 接口测试：覆盖正常、异常、边界、权限、幂等和状态流转。
4. UI、接口和数据库联合验证：拆分 UI 动作、接口断言和数据库只读校验；数据库部分追加读取数据库任务边界。
5. 原生 App 或硬件：明确 Playwright 边界，选择适合工具或人工辅助，不假装能够完全自动化。
6. AI 交叉审核：用户明确要求且能力可用时，可组合子代理、Claude 或多 Agent 独立审核；主代理负责复核和合并结论。

二、标准流程

1. 汇总测试目标、验收依据、环境、已有材料、缺少材料、测试数据和通过标准。
2. 生成可执行用例，至少包含编号、标题、前置条件、步骤、数据、预期、优先级和自动化建议。
3. 明确自动化范围、暂不自动化项、原因、环境与数据要求。
4. 审查脚本的选择器、等待、断言、登录态、数据依赖、清理、日志、截图和 trace。
5. 运行失败时区分脚本、环境、数据、需求和产品缺陷，先补证据，不反复猜测。
6. 需要修复实现或脚本时，切换或组合缺陷修复场景；修复后重新执行相关用例，不删除核心断言掩盖失败。

三、完成输出

输出测试子场景、测试目标、用例与脚本产物、执行结果、失败分类与证据、产品缺陷判断、覆盖缺口、风险、下一步和建议更新的测试文档。
```
