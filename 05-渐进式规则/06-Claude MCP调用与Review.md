# Claude MCP 调用与 Review

## 读取时机

用户要求使用 Claude MCP，或任务需要 Claude 交叉审核、批量杂务、文档维护和复核时读取。

```text
一、固定入口与首次检查

1. Claude MCP Bridge 项目位置：`D:\1poj\学习\claude-mcp-bridge`。
2. 当前会话第一次调用前必须完整阅读：`D:\1poj\学习\claude-mcp-bridge\README.md`。README 与本规则冲突时以当前 README 为准。
3. 不手写 MCP SDK 客户端，统一使用项目的 `mcp-client.mjs`。
4. 调用前先体检：
   `cd D:\1poj\claude-mcp-bridge-ascii`
   `node mcp-client.mjs status`
5. 中文长提示词写入 UTF-8 `promptFile`；多路评审只使用 `node mcp-client.mjs batch @<tasks.json>`。

二、委派原则

1. 不把所有检索、逐文件检查、文档整理和重复验证都留给主 Agent；任务边界清楚时优先交给 Claude 完成。
2. 相信 Claude 的完整产出，主 Agent 负责划定范围、合并结论、处理冲突和复核高风险证据，不重复做一遍相同杂务。
3. 初次调用提供完整上下文、目标、范围、可写路径、禁止项、验证标准和输出格式，预算与时间一次给足，避免碎片化反复调用。
4. 默认 `timeoutMs: 1800000`（30 分钟）。普通完整 Review 建议每任务 `maxBudgetUsd: 2`，复杂业务或大范围文档任务可放宽到 3 至 5；调用前披露任务数、单任务预算和批次理论上限，不设置无限预算。
5. 同一主题的修复或再次复核复用原 `session`；不同主题使用不同 session，避免上下文污染。
6. 批量任务默认并发 3，可按机器资源和任务数量调整。多个任务可能修改同一文件时不得并发写入，应先并行只读审核，再按文件范围串行修复。

三、权限与必要披露

1. 调用前简要披露：Claude 任务划分、工作目录、只读或可写范围、`permissionMode`、session、并发数、30 分钟超时和预算上限。用户已明确触发本流程时直接执行，不重复询问。
2. 只读审核使用 `mode: review` 和 `permissionMode: default`。
3. 获得修改授权的代码修复、注释调整或文档维护可使用 `permissionMode: acceptEdits`，并省略 `mode: review`；可写范围必须写进每个任务提示词。
4. 文档维护 Claude 可创建、重命名、移动、合并和更新 `项目文档/**`，清理冗余时优先合并或移入历史归档；删除操作只限已确认冗余且可由 Git 恢复的文档。
5. Claude 继承常驻安全围栏。即使使用 `acceptEdits`，仍不得未经授权修改数据库、真实外部系统、全局配置、Git 历史或任务范围外文件，不得读取和输出秘密。

四、多维 Review 分工

根据任务实际情况增减任务，不机械固定数量：

1. 字段语义 Review：追踪字段和变量的定义、来源、转换、单位、空值、默认值、枚举、前后端与数据库映射，核对命名和业务含义是否一致，重点发现“类型正确但语义错误”。
2. 业务实现 Review：依据需求、项目文档和现有链路检查业务流程、需求回归、状态流转、权限、事务、异常分支、并发、逻辑漏洞、风险和改造范围。简单任务 1 路，中等任务 2 路，复杂或高风险任务 3 路以上，并让各路从不同流程或风险面独立复核。
3. 代码质量 Review：检查可读性、可维护性、必要可观测性、嵌套和认知复杂度、健壮性、重复代码与过度设计。经授权后可调整结构、补必要注释和日志、降低复杂度并执行局部验证，不改变已确认业务语义。
4. 项目文档维护：只负责项目文档，不修项目代码。按模块和业务细分整理、归纳、合并和更新必要内容，清理冗余；按实际结论处理日志、阶段决策、项目认知、模块认识、工具、成功路径和阶段性事实，无长期价值的内容不写。

五、推荐执行闭环

1. 准备各维度 UTF-8 提示词和一个 batch JSON，字段、业务和代码质量初审使用独立 session，并行执行一次完整只读审核。
2. 汇总所有结果，按证据合并重复问题，标记冲突、严重度、影响范围和推荐方案；不把 Claude 的猜测直接当事实。
3. 需要修复时，优先让提出问题的 Claude 复用原 session 处理。代码范围不重叠可并行，重叠时串行；每个任务一次完成修复、局部验证和结果说明。
4. 代码稳定后再让文档维护 Claude 使用 `acceptEdits` 整理 `项目文档/**`，避免其与业务 Review 同时改动审核依据。文档任务可与不读取项目文档的独立修复并行。
5. 每个阶段至多组织一个批次，不按单个问题反复调用。高风险或存在争议的问题复用原 session 再次复核；低风险且验证充分的改动不机械追加调用。
6. 最终由主 Agent 汇报问题、对应解决方案、已由 Claude 修复的内容、验证证据、未解决风险、Claude session 和维护的文档。
```
