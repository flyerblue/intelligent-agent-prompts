# 初始化文档结构提示词（深化版）

## 适用说明

- 这份用于初始化一个项目的文档与归档骨架
- 重点不是写满，而是先把位置、层级、用途、命名规则和最小模板一次性立住
- 适合新项目、旧项目补规范、归档体系重建，以及把零散文档收敛到统一结构

## 提示词正文

```text
你现在要做的是“初始化文档结构”，不是默认开发任务。

一、执行原则

1. 先检查项目是否已有同类文档；已有则优先复用和对齐，不要机械复制一套平行结构。
2. 先检查全局文档是否存在；不存在时，创建 `D:\1poj\学习\lw-全局文档.md`。
3. 在当前项目目录下，优先复用 `项目文档\开发记忆\`，不要额外新建重复顶层目录。
4. 如果用户没有要求补内容，就只初始化结构，不顺手写大量项目认知。
5. 所有初始化文件只写最小骨架，不预填猜测内容。

二、固定目录

在 `项目文档\开发记忆\` 下固定初始化以下四类目录：

1. `项目总体认知`
2. `项目模块认识`
3. `项目总体日志`
4. `项目模块日志`

三、目录定位

1. `项目总体认知`：放项目整体结构、公共术语、关键链路、跨模块约定、总体边界等稳定认识。
2. `项目模块认识`：放单个模块的职责、边界、依赖、输入输出、数据流、已确认约定等稳定认识。
3. `项目总体日志`：放影响全项目的阶段结论、规则调整、全局风险、跨模块事项、整体推进记录。
4. `项目模块日志`：放某个模块的阶段结论、局部风险、边界变化、遗留问题、止血记录和后续建议。

四、最小文件骨架

1. `项目总体认知` 下至少初始化：
   - `00-项目总览.md`
   - `01-术语与约定.md`
   - `02-模块地图.md`
   - `03-关键链路.md`
   - `04-数据与实体认知.md`
   - `05-风险与边界.md`
2. `项目模块认识` 下至少初始化：
   - `00-模块目录.md`
   - `模块认识模板.md`
3. `项目总体日志` 下至少初始化：
   - `00-项目日志目录.md`
   - `项目日志模板.md`
4. `项目模块日志` 下至少初始化：
   - `00-模块日志目录.md`
   - `模块日志模板.md`

五、模板建议字段

1. 认知类模板建议包含：用途、适用范围、稳定结论、关键边界、相关模块、更新时间、待确认点。
2. 日志类模板建议包含：背景、结论、影响范围、风险、处理状态、后续建议、建议处理时机、关联文档。
3. 目录类文件建议包含：文件清单、维护规则、最近更新、已废弃文档说明。

六、命名规则

1. 总体日志文件名直接写事件主题，例如：`文档归档部分提示词修改.md`。
2. 模块日志文件名推荐使用：`模块名-事项主题.md`。
3. 模块认识文件名推荐使用：`模块名-模块认识.md`。
4. 文件名避免“临时”“最终”“新版”这类含糊词，优先体现对象和主题。

七、更新时机

1. 形成稳定认知时，更新认知类目录。
2. 结论还不稳定、只是阶段发现、临时方案、局部风险或推进记录时，更新日志类目录。
3. 结论影响全项目时写总体层，主要影响单模块时写模块层。
4. 没有新增稳定认知、没有长期价值、没有用户要求时，不写。

八、输出要求

初始化完成后，请说明：

1. 创建或复用了哪些目录和文件。
2. 全局规范写到哪里。
3. 四类项目文档分别写到哪里。
4. 什么时候该写认知，什么时候该写日志。
5. 哪些内容不应该写入文档。
6. 是否发现已有文档冲突或需要人工合并的内容。

文档原则：

- 文档不是默认必写项，优先少而准。
- 初始化的重点是把分类和约束立住，不是一次性写满内容。
- 只初始化骨架，不把过程噪音写进去。
- 所有文档都只是当前认知，可推翻，仅供参考。
```
