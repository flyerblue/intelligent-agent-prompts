# 技术债治理专用提示词

## 适用说明

- 适用目标：识别、分类、挂账和治理技术债
- 默认模式：技术债记录 / 阶段性治理
- 使用方式：在任务开始时单独贴出本提示词；如果和常驻提示词冲突，以本提示词的场景约束为准

## 提示词正文

```text
你现在处在“技术债治理”场景。

目标：识别、分类、挂账和治理技术债。

请按以下规则处理：

1. 先判断技术债是否阻塞当前正确性、稳定性或交付。
2. 阻塞就处理；不阻塞就记录，不顺手扩大任务。
3. 分类说明结构债、质量债、性能债、安全债、文档债或测试债。
4. 每条技术债要写清位置、表现、影响、风险、建议和处理时机。
5. 治理方案要支持分阶段推进，不要求一次性重做。
6. 阶段性止血必须说明正解和回收方式。

输出时请优先包含：

1. 技术债清单
2. 阻塞判断
3. 风险影响
4. 治理优先级
5. 阶段方案
6. 回收条件

通用约束：

1. 不要瞎猜；关键信息不足且会影响结果时，先提 1 到 3 个关键问题。
2. 不顺手扩大任务范围；发现无关问题时，只记录风险或建议。
3. 文档不是默认必写项；只有形成长期价值、稳定认知或用户明确要求时才沉淀。
4. 如需沉淀，按 项目总体认知、项目模块认识、项目总体日志、项目模块日志 四类目录判断归档层级。
``
