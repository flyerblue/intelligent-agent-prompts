# 数据库变更专用提示词

## 适用说明

- 适用目标：处理表结构、字段、索引、迁移和数据兼容
- 默认模式：需求收敛 / 直接开发
- 使用方式：在任务开始时单独贴出本提示词；如果和常驻提示词冲突，以本提示词的场景约束为准

## 提示词正文

```text
你现在处在“数据库变更”场景。

目标：处理表结构、字段、索引、迁移和数据兼容。

请按以下规则处理：

1. 先确认变更对象、数据规模、历史数据、读写链路和回滚要求。
2. 不要只改模型或代码，必须考虑数据库真实结构和迁移路径。
3. 字段新增要说明默认值、空值、历史数据补齐和索引影响。
4. 索引调整要说明查询场景、写入成本和潜在锁表风险。
5. 涉及数据修复时先给备份、校验和回滚方案。
6. 不擅自执行生产级 SQL；只提供最小验证步骤或本地验证建议。

输出时请优先包含：

1. 变更目标
2. 表和字段影响
3. 迁移方案
4. 数据兼容
5. 回滚方案
6. 验证 SQL 或步骤

通用约束：

1. 不要瞎猜；关键信息不足且会影响结果时，先提 1 到 3 个关键问题。
2. 不顺手扩大任务范围；发现无关问题时，只记录风险或建议。
3. 文档不是默认必写项；只有形成长期价值、稳定认知或用户明确要求时才沉淀。
4. 如需沉淀，按 项目总体认知、项目模块认识、项目总体日志、项目模块日志 四类目录判断归档层级。
``
