# 前端设计与实现

## 读取时机

开发、修改或评审前端页面、组件与样式前读取；纯后端、接口与数据层任务不适用。

## 提示词正文

```text
一、先判断情形

前端改动分三种情形，做法完全不同，动手前先归类：

1. 既有系统内修改（最常见）：以项目现有设计体系为准，包括组件库、主题变量和同类页面的既有写法，目标是“像这个团队原有成员写的”；不另起风格，不做任务范围外的顺手美化。
2. 新页面或新项目且没有设计体系：先按第二节定视觉方向，经用户确认后再写代码。
3. 评审或走查已有界面：直接按第四节逐项核对，再按第五节自检。

通用前置：先看项目实际技术栈（package.json、路由、状态管理、样式方案），不按习惯假设是 React 或 Vue；复用既有组件和模式，同类界面第三次重复时再抽公共组件；引入新框架、组件库或动画库前先经用户确认。

二、视觉方向（仅新设计适用）

1. 设计从产品本身出发。先弄清给谁用、在什么场景下用、主要完成什么任务、希望是什么气质；这些从代码里看不出来，能问到就问，问不到就带着自己的判断请用户确认，不闷头脑补后开工。
2. 先出方案再写代码：主色与强调色（4~6 个具名色值）、字体及各自用途、布局与对齐方式、这个页面最想让人记住的一点。风格没说清时出 2~3 个方向，让用户看图选而不是读文字；环境允许时做成可切换的预览页。
3. 大胆只用在一处：留一个记忆点，其余克制；删掉不为内容服务的装饰。
4. 动手前自查：把产品换成另一个行业，如果得出的还是同一套方案，说明这是默认套路而不是为这次需求做的设计，改完再写。
5. 确认后的方向沉淀为项目的设计基线（色值、字体、间距刻度、气质关键词），后续页面沿用，不逐页重新定调。

三、默认套路清单

以下不是禁令：需求明确指定某种风格时照做；需求没限定时，不要把自由度花在这些默认项上。

1. 配色：紫蓝渐变、霓虹光晕、渐变文字、深色底配荧光色、大面积纯黑纯白。
2. 布局：所有内容装进同款圆角卡片加同款阴影、三等分卡片阵列、卡片套卡片、什么都居中、“大数字加小标签”的展示模块。
3. 装饰：彩色粗左边条当强调、到处毛玻璃、无信息量的迷你图表、emoji 当图标、每个标题上方放圆角大图标。
4. 字体与标记：标题里单独给一个词换色或斜体、全大写的小标签、内容不是顺序也编 01/02/03、内容上方多余的分类小标题。
5. 动效：每个区块入场都上滑淡入、每张卡片都加悬停动效、无意义的持续循环动画。
6. 占位内容：张三/李四/Acme 这类占位名、“提升效率、赋能未来”这类空话、凑整的假数据。

四、质量底线

以下任何前端改动都必须满足；已有设计体系时优先用体系自带能力满足，不另造一套。不因“以后再补”“只是原型”“设计还没定”而跳过：事后补的成本是从一开始就做的数倍，原型也经常直接变成正式代码。

1. 可访问性：全流程可用键盘操作；焦点可见，不写没有替代方案的 `outline: none`；新增或修改的文字对比度不低于 4.5:1，体系自带样式不达标时如实报告、不擅自覆盖；图标按钮有可读名称；标题层级不跳级；信息不只靠颜色传达；优先用原生语义元素再考虑 ARIA。
2. 状态完整：加载、空、错误、禁用、成功都有对应呈现；空状态告诉用户下一步做什么；错误说明原因和解决办法；破坏性操作二次确认或可撤销。
3. 表单：有可见标签，不只靠 placeholder；错误提示显示在对应字段旁，提交后聚焦第一个错误；提交按钮加载中保留原文案；触控目标桌面不小于 24px、移动端不小于 44px；移动端输入框字号不小于 16px。
4. 文案即设计：按钮写明会发生什么（“保存修改”而非“提交”）；同一动作全流程用同一个词；用用户能懂的说法而不是系统术语；占位内容也要像真实内容，才能暴露长度、换行和溢出问题。
5. 动效：只动 transform 和 opacity，不写 `transition: all`；尊重 prefers-reduced-motion；动画可被用户操作打断；退出比进入快。
6. 稳定与性能：小屏不横向滚动；图片和异步内容预留位置，不出现布局抖动；长列表虚拟化；不在渲染过程中读取布局。
7. 可分享状态：筛选、分页、标签页等状态同步到 URL，刷新和前进后退不丢。
8. 排版与样式收敛：字号走固定阶梯，相邻层级靠字号和字重拉开差距；长文本限制行宽（西文 65~75 字符）；颜色、间距、圆角、字号走主题变量和既有刻度，不在组件里散落硬编码数值，不用行内样式和深层选择器覆盖。

五、交付前自检

1. “AI 味”测试：把这个界面给人看并说“这是 AI 做的”，对方会立刻相信吗？会就回到第三节逐项排查。
2. 浏览器端验证留证据：截图（含窄屏）、Console/Network 关键输出、关键业务断言，并用键盘走一遍关键流程；按项目声明的目标浏览器范围验证，不做无边界兼容；失败时先区分前端、接口还是数据侧。

默认输出：情形判断与依据；新设计附方案和用户确认结果；改动文件与组件；质量底线自检结果与未满足项；验证证据；剩余风险。
```
