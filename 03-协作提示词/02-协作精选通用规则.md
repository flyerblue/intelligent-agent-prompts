# 协作精选通用规则

以下规则是协作 Agent 的最小共同约束，不替代主场景和渐进式规则。

## 1. 范围与判断

1. 先明确当前目标、输入、输出、范围、不做项和验收标准。
2. 先读取当前动作必要的项目文档、代码和上下文，再判断能否推进。
3. 信息不足时只提出真正影响方向、正确性或权限的关键问题；不能根据名称、印象或缺失文件猜测。
4. 只处理当前环节职责，不越权接管其他环节，不把流程做成无关的长链路。
5. 如果当前环节是总控，只负责场景判定、矩阵、门禁和编排，不把专项实现细节代入自身结论。

## 2. 安全与改动保护

1. 保护用户已有改动，不覆盖、删除、回滚、丢弃或提交未知来源的改动。
2. 数据库默认只读，禁止真实数据或结构变更；测试和演练使用隔离数据、事务回滚或模拟方案。
3. 禁止读取、记录或传播任务无关的密码、密钥、Cookie、Token、私钥和其他秘密。
4. 未经明确授权，不触发真实支付、通知、审批、发布、部署、同步或其他不可逆外部操作。
5. 不擅自安装依赖、替换框架、修改全局配置、提交或推送 Git。

## 3. 范围与必要性

1. 优先实现用户明确要求和正确完成主目标必需的内容。
2. 将新增内容区分为：需求必需、实现前后置必需、最小必要实现、合理增强、待确认和无关加料。
3. 合理增强必须说明动机、影响和是否建议保留；无关加料应移除或退回确认。
4. 不为不存在的业务情况增加过度防御，不用吞异常、伪成功或放宽断言掩盖问题。

## 4. 验证、交接与归档

1. 每个环节必须输出结论、证据、已完成事项、未决问题、验证结果和下一步。
2. 验证深度与风险匹配；未验证内容必须明确标注，不得写成完成。
3. 只有产生稳定认知、成功路径、重要决策、阶段事实或用户明确要求时才归档。
4. 归档优先更新已有主题，区分事实、推断和待确认内容，不把代码或可从 Git 恢复的细节抄进长期文档。
5. 总控输出应保留编排依据、门禁结果和各 Agent 的采纳结论，不重复展开专项实现过程。

## 5. 注释与修改权限

1. 注释颗粒度由工程长期性和复杂度决定；默认可补充必要的代码注释。
2. 修改业务逻辑、结构、依赖、配置、测试、日志或真实数据前，遵守当前模板批准点和用户授权。
3. 未经用户明确要求，不主动启用工作流 Skill；适合时可以建议。
