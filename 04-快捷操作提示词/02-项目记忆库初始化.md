# 项目记忆库初始化

## 操作目标

初始化并检查当前项目基于 Markdown 的开发记忆库，不依赖 Claude Auto Memory。

## 提示词正文

```text
执行“项目记忆库初始化”。

一、确认范围

1. 确认当前项目根目录；不确定时先停下并询问。
2. 项目记忆根目录固定为：`<项目根目录>\项目文档\开发记忆\`。
3. 本操作不修改 `.claude`、Codex 配置、Git 历史或任何数据库。

二、先检查再初始化

1. 检查并读取已有开发记忆目录、索引和相关文档，不直接覆盖。
2. 缺失且确有用途时，按以下结构创建：
   - `项目总体认知\`
   - `项目模块认识\`
   - `项目总体日志\`
   - `项目模块日志\`
   - `阶段决策\`
   - `成功路径\`
   - `开发过程\`
   - `历史归档\`
   - `工具目录\`
3. 每类目录缺少索引时，创建对应 `00-...目录.md`；索引只记录主题、文件和一句话用途，不堆正文。
4. 没有实际内容时不强行创建大量主题文件。

三、长期维护纪律

1. 写入前先检索已有文档；能更新原主题就不重复新增。
2. 一个认知文件只维护一个清晰主题；日志文件名直接体现事件或模块事项。
3. 目录索引以 150 行或 20KB 为日常软上限，避免接近 200 行或 25KB；正文按主题拆分，不用单个巨型文件承载全部历史。
4. Git、代码和项目文档中已明确存在且容易重新获得的内容不重复抄写。
5. 密码、密钥、Cookie、Token、私钥和其他秘密永不写入记忆。
6. 临时推测只留当前会话；阶段结论写日志；稳定且经确认的认识写认知。
7. 新结论推翻旧结论时更新主认知，并在对应日志记录旧结论失效、替换原因和影响范围。
8. 所有文档只是当前认知，可推翻，仅供参考。

四、初始化检查

1. 检查重复主题、同义目录、冲突结论、过大索引、混合主题和可能的敏感信息。
2. 拿不准是否合并、删除或迁移时先列出建议，不自行处理。
3. 不显示发现的秘密正文，只报告文件路径、信息类型和建议动作。

五、完成汇报

1. 当前项目根目录和记忆根目录。
2. 创建、修改、复用和跳过的文件。
3. 各索引当前行数与字节数。
4. 重复、冲突、容量和敏感信息风险。
5. 需要用户确认的后续动作。
```
