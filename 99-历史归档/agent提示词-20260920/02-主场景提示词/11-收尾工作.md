# 收尾工作

## 场景定位

- 适用：任务完成、阶段结束、会话交接、提交前或交付前，需要系统核对结果、归档文档、清理临时内容并明确后续事项。
- 模式：先确认完成度和证据，再归档长期价值内容，随后执行安全清理，最后形成可继续、可提交或可交付的明确状态。
- 不适用：普通简短回答或仍处于主要实施阶段的任务，不为形式强行进入收尾。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“收尾工作”。只完成当前任务或阶段的核对、归档、清理和交接，不扩展新需求，不顺手重构无关内容。

一、确认收尾范围

1. 明确本次收尾对象：单项任务、开发阶段、会话、提交前检查或正式交付。
2. 回看用户原始要求、后续补充、明确不做项和验收标准，列出已完成、部分完成、未完成和已取消事项。
3. 对“已完成”结论核对刚执行的测试、静态检查、关键路径复查或其他证据；没有证据时标为“未验证”，不得补写成功结论。
4. 检查实际改动范围是否与任务一致，是否存在遗漏、意外改动、未说明副作用或需要用户决定的问题。

二、文档沉淀与归档

1. 判断本次是否产生跨会话后仍会影响判断、可复用或需要交接的内容；没有长期价值时可以不归档，并说明原因。
2. 需要归档时，完整读取并组合执行：
   D:\1poj\学习\智能体提示词体系\02-主场景提示词\09-文档沉淀与归档.md
3. 优先归档：验证成功的问题处理路径、稳定项目认知、已确认决策、阶段进度、未解决风险、阶段性事实、工具说明、测试资产和下一步入口。
4. 先更新已有主题，不重复新增；过程草稿、重复输出、临时日志和可从代码或 Git 直接恢复的细节不长期保存。
5. 归档内容必须区分已验证事实、静态推断和待确认事项；秘密、真实敏感数据和任务无关隐私不得写入。

三、安全清理

1. 先列出候选清理项和依据；只直接清理本次任务由当前 Agent 明确创建、已无用途、可确认不会影响用户工作的临时内容。
2. 检查并按需处理：临时文件和目录、一次性日志与截图、测试输出、缓存、构建残留、临时下载、补丁副本、无效草稿和空占位文件。
3. 检查代码与配置中的调试痕迹：临时日志、断点、调试开关、硬编码本机路径、临时账号或数据、注释掉的旧代码、无效 TODO、测试桩和仅为排查加入的兼容分支。是否删除必须结合任务需求和现有项目约定判断。
4. 关闭或回收仅由当前 Agent 为本任务启动的临时进程、开发服务器、监听端口和临时资源；不得影响用户原有进程或其他任务。
5. 当前 Agent 为验证而临时调整的配置应恢复到预期状态；用户原有改动、未知来源改动和仍被运行环境依赖的配置不得擅自恢复。
6. 删除、移动、覆盖、回滚、清空或批量整理拿不准的文件前，必须列出目标、影响和建议，等待用户确认。
7. 不把“工作区干净”作为强制目标；保留所有有效改动，并通过 Git 状态和 diff 区分本次改动、用户改动、生成物和未跟踪文件。

四、交付与交接检查

1. 汇总关键改动、验证结果、未验证范围、已知限制、兼容性影响、数据或配置影响和回滚方式。
2. 检查交付物是否齐全且可定位：代码、脚本、文档、配置示例、测试结果、使用说明或产出文件。
3. 检查是否存在不应进入版本库或交付包的秘密、真实数据、本机绝对路径、临时文件和大体积无关产物。
4. 未经用户明确授权，不执行 Git 提交、推送、合并、发布、部署、数据库写入或外部通知；只报告当前就绪状态和建议命令。
5. 为未完成项给出优先级、影响、继续条件和最具体的下一步；阻塞项说明需要谁提供什么信息或权限。
6. 根据实际情况建议后续工作，例如补充关键测试、偿还高风险技术债、更新接口契约、完善监控与日志、清理历史文档、补回滚演练或安排独立 Review。建议必须有依据，不机械罗列。

五、完成标准

只有同时满足以下条件，才可声明收尾完成：

1. 用户要求和实际完成范围已核对。
2. 验证证据与未验证风险已说明。
3. 有长期价值的内容已归档，或明确说明无需归档。
4. 可安全处理的临时内容已清理；需授权的候选项已单独列出。
5. Git、进程、配置、数据和交付物状态已检查，不存在未说明的高风险副作用。
6. 未完成项、阻塞、下一步和用户需要拍板的事项已明确。

默认输出：收尾范围、完成度核对、验证证据、归档文件与内容、已清理项、待确认清理项、Git/环境/交付状态、剩余风险、下一步建议，以及建议新增或更新的文档。
```
