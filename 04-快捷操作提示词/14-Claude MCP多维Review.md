# Claude MCP 多维 Review

## 操作目标

通过 Claude MCP Bridge 完成字段语义、业务实现、代码质量和项目文档四个维度的并行审核、必要修复与复核。

## 提示词正文

```text
执行“Claude MCP 多维 Review”。不要把可委派的逐文件检查和文档整理全部由主 Agent 重做。

一、前置读取

1. 完整读取并遵守：
   D:\1poj\学习\智能体提示词体系\05-渐进式规则\06-Claude MCP调用与Review.md
2. 当前会话第一次调用 Claude MCP 前，完整读取：
   D:\1poj\学习\claude-mcp-bridge\README.md
3. 先在 `D:\1poj\claude-mcp-bridge-ascii` 运行：
   `node mcp-client.mjs status`
4. 状态检查失败时停止调用，汇报失败证据和修复建议，不自行重装或改全局配置。

二、调用前披露

先用简短清单告诉用户：项目工作目录、Review 维度及任务数、只读和可写范围、session 命名、并发数、`timeoutMs: 1800000`、预算上限和明确禁止项。用户通过本快捷操作已授权执行，不重复等待确认。

三、建立任务

根据当前改动规模生成 UTF-8 提示词和一个 batch JSON：

1. 字段语义任务 1 路：核对字段、变量来源、含义、映射、单位、默认值、空值、枚举和语义漂移。
2. 业务实现任务：简单改动 1 路，中等改动 2 路，复杂或高风险改动 3 路以上；分别检查业务流程、需求回归、逻辑漏洞、权限、状态、事务、异常、风险和改造边界，并交叉验证。
3. 代码质量任务 1 路：检查可读性、可维护性、必要可观测性、嵌套复杂度、健壮性和过度设计。
4. 文档维护任务 1 路：在代码 Review 和必要修复完成后维护 `项目文档/**`，按模块和业务细分整理日志、决策、认知、工具、成功路径和阶段性事实；不修项目代码，不写无意义文档。

初审代码任务统一使用 `mode: review`、`permissionMode: default` 和独立固定 session。全部任务默认 30 分钟超时；普通 Review 每任务预算建议 2 美元，复杂业务或大范围文档任务可放宽到 3 至 5 美元。一次给足上下文和验收标准，并披露单任务预算和批次理论上限。

四、执行与修复

1. 字段、业务和代码质量初审只通过 `node mcp-client.mjs batch @<tasks.json>` 执行，默认并发 3。
2. 主 Agent 只做结果聚合、证据核对和冲突裁决，不重新做一遍 Claude 已完成的杂务。
3. 汇总问题后，可让提出问题的 Claude 复用原 session 修复。修复任务使用 `permissionMode: acceptEdits`，明确可写文件、禁止项和验证要求；重叠代码范围串行执行。
4. 代码质量 Claude 可在不改变业务语义的前提下调整结构、补必要注释和可观测性、降低复杂度并验证。
5. 代码稳定后再运行文档维护任务，使用 `permissionMode: acceptEdits`，明确只允许修改 `项目文档/**`；可以整理、移动、合并和更新文档，但不修改项目代码。
6. 每个阶段至多一次批量调用，不按单个问题反复调用。再次复核优先复用原 session，只复核高风险、争议或修复过的问题。

五、最终输出

1. Review 任务、Claude session、权限、预算、耗时和状态。
2. 按严重度整理的问题、证据、影响范围和对应解决方案。
3. Claude 已修改的代码与文档、执行的验证及结果。
4. 交叉审核存在的分歧和最终判断。
5. 未解决风险、需要用户决定的事项，以及建议新增或更新的文档。
```
