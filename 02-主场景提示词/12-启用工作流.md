# 启用工作流

## 触发条件（判据，任一为是）

1. 用户明示"用工作流"或指定 saved 工作流。
2. 任务满足以下任一：跨会话长链路；需多子代理协作（复核/评审/分工）；需确定性检查与门禁（测试门禁、G2 待执行清单）。

**不进工作流**（常驻直推）：快速问答与小修（直接开发/直接回答场景）；交接接手（按 `05-渐进式规则\10-上下文交接.md` 横切执行）；护栏运维（`06-同步工具` 脚本 + 人工授权）。拿不准时说明价值并建议，不主动启用。

**不适合时的告知确认**：判据不满足或明显过重（工作流开销大于收益，如单点小修、纯问答）时告知用户确认，不默默改道也不硬开——用一两句说明不适合的理由（复杂度低/一次通过性高/无多代理与门禁需求），请用户确认走常驻直推还是仍开工作流（此时可建议快速档）；用户未点名工作流且明确不适合时直接常驻直推，不额外打扰。

**多端说明**：本场景的动态工作流机制（saved 骨架、escalation、确定性门禁）当前仅 ZCode 支持；其他 agent（codex/claude/ccgui/paseo）命中判据时，说明价值并建议用户转 ZCode 执行，或退回常驻直推。

## 入口动作（按序）

1. 读取工作流偏好：
   ```text
   D:\1poj\学习\智能体提示词体系\07-工作流体系\02-工作流偏好.md
   ```
2. 判断模板（任务类型 → 投影；模板与档位语义见 `07-工作流体系\01-工作流体系设计.md` 第三节）：
   - 异常/报错/受控变更 → 修改流
   - 新功能/重构面广 → 新功能流
   - 新平台/新技术调研 → 调研流
   - 准备合入/部署 → 发布流
   - 无完全匹配 → 读相近模板组合（场景自由组合原则），或按「不适合时的告知确认」请用户确认后退回常驻直推
3. 弹首发档位问：快速/标准（默认推荐）/严格 三选一，推荐项=偏好文件里的默认档位；用户已指定档位、明示"按默认别再问"、或全自动开关开启时跳过。
4. 现场生成并发起：以 `D:\1poj\学习\智能体提示词体系\.zcode\workflows\workflow-skeleton.dwf.ts` 为**母版**，只保留本任务所需的投影与档位分支（其余分支删除），按任务定制角色挂载、循环上限与门禁点，生成新脚本经确认窗口发起。裁剪次序：先按复杂度定并行度（小修改/单点任务单线推进，面广可独立分工才开多路），再按「一次通过性 × 安全要求」定门禁点（高确定性低风险用档位默认；新领域/历史易错/不可逆/核心数据才加密）——超出档位默认的并行分支与门禁点各附一句理由，无理由即删。生成时必须守住设计文档第四节运行规则（编排强度、G2 清单制、循环上限、循环内门禁、角色文件首读+版本标记）；用户要标准组合且无定制需求时，也可直接以母版 args(task/template/tier) 运行。

## 运行中纪律

1. G1 拍板由主代理弹问；G2 一律待执行清单制，不进子代理权限。
2. 多路产物由下一阶段收拢或门禁协调员打包，不设专职汇总角色。
3. 实施与验证为有界循环（标准≤2轮、严格≤3轮、快速无循环）：退回修改→带评审意见自动重做；退回澄清→循环内门禁请人工补充信息；超限→人工决策（接受现状收尾/终止/指示另起）。
4. 用户中途新输入：先挂起攒批，阶段间隙或结束后一次注入（热修订成本考虑）。
5. 运行中随时可交接；方案变更用热修订不重跑。
