# 测试执行边界

## 读取时机

设计、生成、执行、修改或审核任何测试前读取。

```text
一、测试选择

1. 先确定测试目标、风险、已有框架和通过标准，再选择只读审核、交叉审核、单元、集成或端到端测试。
2. 优先最小且能证明目标的测试；共享行为或跨模块契约变化时扩大覆盖。
3. 子代理、Claude 或多 Agent 交叉审核只在用户要求且能力可用时启用；不可用时说明降级方案，不伪造审核结果。

二、执行安全

1. 测试默认不得修改真实持久数据或触发真实支付、通知、审批、发布和外部同步。
2. 需要写入时使用隔离环境、专用测试数据、模拟服务或可回滚事务，并验证回滚结果。
3. 不把生产凭据、真实个人信息或秘密写进测试代码、快照、截图、trace 和日志。
4. 未确认环境时不执行具有外部副作用的测试。

三、测试质量

1. 用例覆盖前置条件、步骤、数据、预期和优先级，区分正常、异常、边界、权限和状态流转。
2. 断言业务结果，不只断言命令退出、页面出现或接口返回 200。
3. 测试失败时保留最小复现、日志、截图或 trace，区分实现、脚本、环境、数据和需求问题。
4. 不通过删断言、加固定等待、跳过核心用例或放宽成功条件制造通过结果。
5. Playwright 优先使用 `data-testid`、role、label、placeholder、text 和稳定 CSS；避免坐标、脆弱 XPath 和固定等待。
6. 完成时汇报执行命令、通过与失败数量、失败证据、未覆盖范围和剩余风险。
```
