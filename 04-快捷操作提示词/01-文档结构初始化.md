# 文档结构初始化

## 操作目标

参考 `D:\1poj\AOUTpoj\gzgf\项目文档` 的领域归档方式，以及 `D:\1poj\Apoj\sthjjcddglpt1\项目文档` 的模块标准包、权威索引、测试资产和专项工作区，为当前项目建立与复杂度匹配的文档结构。

初始化或新接手项目时，可按需使用 `archify` 生成代码结构、依赖关系和项目上下文，作为理解辅助；生成内容必须经过人工和 Agent 复核，不替代源码、文档和运行证据。

## 提示词正文

```text
执行“文档结构初始化”。这是项目探索与文档操作，不是默认开发任务。

一、选择初始化子场景

1. 新项目初始化：没有同类结构时，创建基础层最小骨架。
2. 现有项目补齐：复用已有目录，只补缺失且当前确有用途的分类、索引或模块目录。
3. 旧结构整理：先输出旧目录到推荐结构的映射、重复、冲突和迁移顺序；未经确认不移动、不删除、不重命名。
4. 新模块扩展：结构已存在时，只识别新模块并补对应业务模块、模块认识、模块日志和成功路径入口。
5. 复杂项目增强：长期维护、模块多、需要系统性治理、测试资产或重构工作流时，按证据增加标准模块包和可选增强层。

二、执行前探索

1. 确认项目根目录；无法确定时只询问这一项，不继续创建。
2. 阅读 README、AGENTS.md、CLAUDE.md、现有项目文档、主要源码目录、路由、命名空间、模块配置、接口和实体映射。
3. 若项目包含数据库，优先在隔离位置导出脱敏后的表结构和必要样例数据，放入 `资料\数据库文档\`；禁止把密码、连接串、Token、个人信息或生产秘密复制进仓库。数据库默认只读，导出前确认范围和脱敏方式。
4. 识别项目类型、维护周期、协作规模、主要业务模块、共享基础能力和当前专项工作。
5. 每个模块判断至少保留一项证据：代码目录、命名空间、路由、Controller、表、配置或已有文档。
6. 证据明确的模块可以自动创建目录；只有名称猜测或边界不清的模块列为“待确认”。
7. 扫描已有索引、同义目录、混合文档、大体积会话记录和重复内容；先复用，不机械建立平行体系。

三、基础层推荐结构

所有项目优先建立或复用以下结构：

项目文档\
├── 00-入口\
│   ├── 文档地图.md
│   ├── 权威文档索引.md
│   └── 模块清单.md
├── 产出\
│   └── <交付主题>\
├── 接口文档\
│   └── <业务模块或协作主题>\
├── 开发记忆\
│   ├── 项目总体认知\
│   ├── 项目模块认识\
│   ├── 项目总体日志\
│   ├── 项目模块日志\
│   ├── 阶段决策\
│   ├── 成功路径\
│   │   ├── 通用成功路径\
│   │   └── <模块名>\
│   ├── 开发过程\
│   ├── 历史归档\
│   └── 工具目录\
├── 业务模块\
│   ├── 共享基础\
│   └── <模块名>\
└── 资料\
    ├── 阶段性事实\
    │   └── <模块名>\
    ├── 外部接口文档\
    │   └── <外部系统或领域>\
    ├── 数据库文档\
    │   ├── 表结构\
    │   ├── 示例数据\
    │   └── 数据库变更\
    └── 参考资料\

不使用 `lw-` 前缀，不同时保留“模块日志/项目模块日志”“项目认知/项目总体认知”等同义目录，不默认创建“待整理会话”或复制原始聊天记录。

四、入口与索引文件

1. `文档地图.md`：说明目录职责、推荐阅读顺序、主要入口和维护规则。
2. `权威文档索引.md`：列出各主题当前有效文档、回答的问题、证据状态、是否能指导实施，以及旧文档失效或降级关系。项目较小时可与文档地图合并。
3. `模块清单.md`：记录模块编号或名称、业务职责、代码根目录、依赖、Owner 或维护方、文档完整度和待确认事项。
4. 发生结论冲突时，先更新权威索引，再在总体日志记录旧结论失效原因和影响范围。

五、开发记忆最小文件

1. `项目总体认知\`：初始化 `00-项目总览.md`、`01-术语与约定.md`、`02-模块地图.md`、`03-关键链路.md`、`04-数据与实体认知.md`、`05-风险与边界.md`。只写已确认的项目级稳定事实。
2. `项目模块认识\`：中小模块默认使用 `<模块名>.md`；单文件过大或包含多个业务子域时改为 `<模块名>\`，再按子业务拆分。记录稳定职责、边界、依赖、数据流和关键约定，不复制完整代码清单。
3. `项目总体日志\`：记录跨模块推进、全局规则变化、整体风险和阶段状态。
4. `项目模块日志\<模块名>\`：按事项或日期记录模块阶段结论、临时方案、风险、遗留和处理时机。
5. `阶段决策\`：一项决策一个主题，记录背景、选项、取舍、结论、证据、影响范围和失效条件。
6. `成功路径\`：通用经验放 `通用成功路径\`，业务问题按模块存放。字段至少包含适用场景、问题表现、上下文与影响、根因证据、正确处理路径、关键文件、验证结果、可复用经验和不适用范围。
7. `开发过程\<模块名>\<日期-主题>\`：只保存阶段计划、上下文恢复和实施跟踪；完成后提炼到认知、决策或成功路径，原过程按需移入历史归档。
8. `工具目录\`：记录工具用途、源码或产物位置、输入输出、配置、风险、验证、回滚和使用说明。

六、业务模块文档分级

根据项目复杂度选择，不为每个模块机械创建空文件：

1. 简单模块：只创建 `业务模块\<模块名>\模块说明.md`，覆盖职责、主要流程、入口、数据和风险。
2. 中长期或复杂模块：采用标准模块包：
   - `00-模块索引.md`：阅读顺序、文档状态、边界和关联模块。
   - `01-代码地图.md`：前后端入口、路由、Controller、Service、Mapper、Entity、配置和证据锚点。
   - `02-链路与数据模型.md`：业务场景、调用链、状态流转、核心表、字段语义、外部副作用、跨模块依赖和风险。
   - `03-模块SOP.md`：角色、前置条件、操作流程、异常分支、验证方式和恢复步骤。
   - `04-变更契约.md`：仅在重构、大改或迁移时创建，记录目标边界、不变量、门禁、兼容、迁移、切换、回退和未决裁决。
   - `sop.html`：仅在需要离线浏览、导航、打印或交付展示时生成，不作为 Markdown 的第二事实源。
3. `业务模块\共享基础\`：项目确有跨模块公共能力时创建，可使用 `01-能力地图.md`、`02-复用约定.md`、`03-接入SOP.md`。
4. `项目模块认识` 保存稳定摘要，`业务模块` 保存详细业务与实现材料；两者通过链接关联，不重复粘贴正文。

七、可选增强层

只有项目实际需要时创建：

1. `测试资产\`：适用于需要可复用接口、数据库或端到端测试夹具的项目。
   - `_模板\`：保存 manifest、request、expected、side-effects、rollback、db-delta 等空模板。
   - `<Case-ID>\`：保存请求、预期、数据变化、外部副作用、回滚说明和脱敏基准快照。
2. `专项工作区\<专项或模块>\`：适用于大型重构、迁移、专项治理或多阶段交付。
   - `00-专项发起\`：目标、范围、角色和任务提示。
   - `01-上下文与探索\`：现状、证据和探索结论。
   - `02-方案及验证\`：实施方案、测试、门禁和回退。
   - `03-交付结果\`：完成情况、验证、风险和后续项。
   - 可建立 `公共工作区\` 保存任务看板、模板和角色提示词。
3. `产出\<主题>\`：适用于项目归档方案、全项目 SOP、重构初始化、静态 Wiki、报告或其他明确交付物；不得把过程草稿长期混在产出中。
4. `.obsidian\`、LLM Wiki、离线站点、预览图片和任务树属于工具或交付特例，不作为默认初始化内容。

八、分类边界

1. `00-入口` 只导航和声明权威关系，不堆正文。
2. `产出` 存放面向用户或外部交付的最终方案、报告和制品。
3. `接口文档` 存放项目自身维护的接口契约；外部系统原始接口文档放 `资料\外部接口文档`。
4. `开发记忆` 存放认知、日志、决策、成功路径、过程和工具经验。
5. `业务模块` 按领域保存可供理解业务和实现链路的详细材料。
6. `资料` 存放项目外输入、阶段事实和数据库参考；示例数据和快照必须脱敏。
7. `测试资产` 只保存可复用、可清理、可回滚的测试输入和证据，不保存真实生产秘密。
8. `专项工作区` 是阶段性执行空间，完成后必须提炼结论并归档，不得成为第二套永久开发记忆。

九、创建规则

1. 新项目只创建基础目录、入口文件和已确认模块入口；没有内容时不批量生成完整模块包。
2. 识别到长期复杂模块时，可创建标准模块包的文件名和最小用途说明，但不得预填猜测事实。
3. 目录无法被 Git 保存时，可创建最小 `README.md` 或 `00-目录.md` 说明用途；不创建无意义占位文件。
4. 已有文件不覆盖、不清空、不擅自改名；发现同义旧目录时给映射、优先级和迁移建议。
5. 权威索引、稳定认知和模块清单必须区分“代码确认、配置确认、静态推断、待数据库核验、待业务核验、待运行核验”。
6. 不复制参考项目的业务内容、秘密、连接串、Token、真实示例数据、大体积会话记录或项目专属数字。

十、完成汇报

1. 项目根目录和选择的初始化子场景。
2. 创建、复用和跳过的目录与文件。
3. 识别的模块、共享基础能力及证据。
4. 采用简单模块说明还是标准模块包，以及判断理由。
5. 已有旧结构的映射、重复、冲突和迁移建议。
6. 可选增强层是否需要创建；未创建时说明原因。
7. 待确认模块、未写入内容和安全风险。
```
