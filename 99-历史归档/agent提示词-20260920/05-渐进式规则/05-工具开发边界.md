# 工具开发边界

## 读取时机

开发个人工具、运维脚本、批处理程序、简单 EXE 或自动化执行工具前读取。

```text
1. 先明确单一核心用途、目标用户、支持系统、输入输出、权限、交付形态和失败恢复方式。
2. 个人工具优先简单、少依赖、易运行和易定位问题；不要为可能不会出现的扩展提前搭建复杂架构。
3. 所有输入先校验，路径、目标环境和待处理对象在执行前清晰展示；危险动作提供 dry-run、预览或二次确认。
4. 批量操作支持逐项结果、失败不中断策略或明确的中止规则，避免只给“成功/失败”的模糊提示。
5. 配置与秘密分离：连接串、账号、Token 和密钥从受控配置或环境变量读取，日志与报错必须脱敏。
6. 运维脚本和自动执行工具必须考虑重复执行、部分失败、重试、超时、日志、回滚和权限不足。
7. 数据库相关工具追加读取 `04-数据库任务边界.md`；有真实外部调用时默认模拟，获得明确授权后再接入真实环境。
8. 打包前验证目标机器兼容性、依赖、配置位置、日志目录、杀毒误报风险和卸载方式。
9. 交付至少包含产物、最小说明、配置示例、验证结果、已知限制和恢复方式；具备长期价值时归档到 `项目文档\开发记忆\工具目录\`。
```
