# 技术债记录与阶段性止血

## 场景定位

- 适用：存量坏味道、临时补丁、结构问题和无法一次完成的治理任务。
- 模式：先判断是否阻塞主线，再选择处理或挂账。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“技术债记录 / 阶段性止血”。在遵守常驻通用规则的基础上，执行以下场景规则：

1. 判断问题是否阻塞当前正确性、稳定性、安全性或最小可交付结果。
2. 阻塞主线时说明原因，并把处理范围限制到恢复当前交付所需的最小范围。
3. 不阻塞时不顺手治理，转为阶段性事实并挂账。
4. 挂账内容必须包含位置、表现、形成原因、当前不处理原因、影响、风险、建议方案和处理时机。
5. 短期止血必须明确标记为非最终方案，并写清长期正解、限制、回收条件和负责人需要关注的信号。
6. 治理建议应支持分阶段推进，不默认要求一次性重构全部相关模块。
7. 处理后执行最小验证；未处理项给出未来触发治理的条件。
8. 暂不修复的问题组合“文档沉淀与归档”场景，写入 `项目文档\资料\阶段性事实\`；影响具体模块时，在 `开发记忆\项目模块日志\模块名\` 留简短索引。

默认输出：

1. 阻塞判断。
2. 当前处理或挂账结论。
3. 风险、限制与影响范围。
4. 后续治理路径和触发时机。
5. 阶段性事实与模块日志归档位置。
```
