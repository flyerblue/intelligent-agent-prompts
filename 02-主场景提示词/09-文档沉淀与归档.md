# 文档沉淀与归档

## 场景定位

- 适用：把已验证结论、成功路径、项目认知、决策、阶段事实或外部资料写入项目文档。
- 模式：先判断归档子场景和长期价值，再写入唯一合适位置。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“文档沉淀与归档”。先读现有项目文档，复用已有目录和主题文件，不覆盖用户内容，不重复建立同义目录。

一、选择归档子场景

1. Bug 或问题已解决：按业务或技术模块写入 `项目文档\开发记忆\成功路径\模块名\`。内容包含适用场景、问题表现、上下文与影响、根因证据、正确处理路径、关键文件、验证结果、可复用经验、风险与不适用范围。
2. 项目探索完成：稳定的整体认知写入 `开发记忆\项目总体认知\`；模块职责、边界、依赖和数据流写入 `开发记忆\项目模块认识\模块名\`。未确认推断不得写成稳定事实。
3. 决策完成：写入 `开发记忆\阶段决策\`，记录背景、选项、取舍、结论、证据、影响范围、验证和失效条件。
4. 问题暂不修复：写入 `项目文档\资料\阶段性事实\`；若影响某模块后续推进，再在 `开发记忆\项目模块日志\模块名\` 留简短索引。记录现象、证据、不处理原因、风险、后续建议和处理时机。
5. 项目外输入：接口文档放 `项目文档\资料\外部接口文档\`，数据库说明和示例数据放 `资料\数据库文档\`，其他参考输入放 `资料\参考资料\`。项目自身维护的接口契约放 `项目文档\接口文档\`。
6. 项目级过程与阶段进度：跨模块内容写 `开发记忆\项目总体日志\`，模块内容写 `开发记忆\项目模块日志\模块名\`。
7. 可交付文件写入 `项目文档\产出\`；工具源码、说明或交付记录写入 `开发记忆\工具目录\`。

二、写入规则

1. 先检索同主题文档；能更新就不重复新增。
2. 新结论推翻旧结论时更新主文档，并在日志记录旧结论失效、原因和影响范围。
3. 结论不稳定时先写日志或阶段性事实，确认后再上收为认知。
4. 压缩抽象，不复制大段代码、SQL、聊天记录或可从仓库轻易恢复的内容。
5. 密码、密钥、Cookie、Token、私钥、真实个人信息和其他秘密永不写入。
6. 不确定是否值得写或放在哪里时，列出候选位置和理由，等待用户确认。

默认输出：归档子场景、创建或更新的文件、核心新增内容、未归档内容及原因、建议新增或更新的文档。
```
