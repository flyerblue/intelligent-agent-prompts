# 测试与验证

## 场景定位

- 适用：测试设计、测试执行、质量审核、交叉审核和回归验证。
- 模式：先选择测试子模式，再按风险组合执行。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“测试与验证”。先读取：
D:\1poj\学习\智能体提示词体系\05-渐进式规则\03-测试执行边界.md

一、选择子模式

根据目标选择一个主测试模式；确有必要时组合多个：

1. 只读审核：审查需求、实现、用例、日志或差异，不修改代码和数据。
2. 子代理审核：把边界独立的检查项交给子代理，主代理复核证据并统一结论。
3. Claude 交叉审核：先读取 `D:\1poj\学习\智能体提示词体系\05-渐进式规则\06-Claude MCP调用与Review.md`，通过 Claude MCP Bridge 独立复查；不可用时明确降级，不伪造结果。
4. 多 Agent 交叉审核：不同 Agent 独立检查不同风险面，主代理去重、处理冲突并负责最终结论。
5. 单元测试：验证函数、类或组件的局部行为和边界。
6. 集成测试：验证模块、接口、数据库或外部依赖之间的协作。
7. Playwright 测试：验证浏览器关键流程、界面状态和业务结果。

二、执行规则

1. 明确测试对象、依据、环境、数据、范围、不测项和通过标准。
2. 先复用现有测试框架、夹具、数据和命令；不为单次测试另建平行体系。
3. 根据风险覆盖成功、失败、边界、权限、状态流转和回归路径。
4. 失败时区分产品缺陷、测试脚本、环境、数据和需求问题，保留可复查证据。
5. 不删除关键断言或放宽通过条件来掩盖失败。
6. 涉及数据库时追加读取数据库任务边界；涉及代码修改时追加读取代码质量与注释规则。
7. 使用 Claude MCP 时，把字段语义、业务实现、代码质量和文档维护拆成边界清楚的任务；主 Agent 聚合结果和复核高风险证据，不重复全部检查。
8. 交叉审核只增强证据，不代替主代理对最终结论负责；多个结论冲突时说明证据和未决点。

默认输出：测试模式、范围与依据、执行结果、失败分类、证据、覆盖缺口、Claude session 与分歧、风险和文档建议。
```
