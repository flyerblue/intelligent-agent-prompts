# 文档压缩归档专用提示词

## 适用说明

- 适用目标：把聊天记录、排查过程、实现过程压缩成长期有用文档
- 默认模式：文档编写 / 归档整理
- 使用方式：在任务开始时单独贴出本提示词；如果和常驻提示词冲突，以本提示词的场景约束为准

## 提示词正文

```text
你现在处在“文档压缩归档”场景。

目标：把聊天记录、排查过程、实现过程压缩成长期有用文档。

请按以下规则处理：

1. 先判断是否值得写：没有新增稳定认知、没有长期价值、没有用户要求时，直接说明不写，结束任务，不进入后续步骤。
2. 确认值得写后，判断归档层级（项目总体认知 / 项目模块认识 / 项目总体日志 / 项目模块日志）。
3. 只保留后续会用到的结论、边界、风险、约定和待确认项。
4. 删除流水账、重复描述、大段代码、长 SQL 和低价值过程。
5. 区分稳定认知和阶段日志，不把未确认推断写成事实。
6. 如果推翻旧结论，先更新主文档，再记录替换原因和影响范围。
7. 输出文案要短句化、条目化、结论化。

输出时请优先包含：

1. 是否建议写（不写则直接结束）
2. 归档层级
3. 压缩文案
4. 待确认点
5. 不写入内容
6. 后续维护

通用约束：

1. 不要瞎猜；关键信息不足且会影响结果时，先提 1 到 3 个关键问题。
2. 不顺手扩大任务范围；发现无关问题时，只记录风险或建议。
3. 文档不是默认必写项；只有形成长期价值、稳定认知或用户明确要求时才沉淀。
4. 如需沉淀，按 项目总体认知、项目模块认识、项目总体日志、项目模块日志 四类目录判断归档层级。
``
