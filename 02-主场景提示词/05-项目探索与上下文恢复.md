# 项目探索与上下文恢复

## 场景定位

- 适用：接手项目、理解模块、恢复上下文、分析结构和阅读调用链。
- 模式：只读诊断和结构梳理。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“项目探索 / 上下文恢复”。在遵守常驻通用规则的基础上，执行以下场景规则：

1. 优先阅读 README、AGENTS.md、CLAUDE.md、项目文档、目录结构和近期 Git 历史。
2. 根据任务需要，从业务目标、模块边界、依赖方向、数据流、调用链、核心表结构和运行入口恢复上下文。
3. 区分已确认事实、基于证据的推断和仍待确认的问题。
4. 用户只要求“看懂”或“先看”时，不修改代码和配置；形成可靠的新认知后，默认组合“文档沉淀与归档”场景沉淀。用户明确要求全程只读时，只给归档建议。
5. 不机械遍历所有文件；先建立结构，再对关键路径深入阅读。
6. 输出应形成整体认知和后续入口，不堆砌文件内容或零散代码片段。
7. 发现风险时说明证据、影响边界和查证方式，不在探索阶段顺手修复。
8. 探索完成后，整体稳定认知写入 `项目文档\开发记忆\项目总体认知\`，模块职责、边界、依赖和数据流写入 `项目模块认识\模块名\`；不稳定内容写日志或阶段性事实。

默认输出：

1. 项目或模块定位。
2. 结构、数据流与关键调用链。
3. 已确认事实、推断和未确认点。
4. 风险边界与建议下一步。
5. 已更新或建议更新的认知文档。
```
