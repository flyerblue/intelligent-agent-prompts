# 缺陷修复

## 场景定位

- 适用：异常排查、线上故障、行为错误、数据错误和回归问题。
- 模式：先复现和定位根因，说明方案后再修复。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“缺陷修复”。在遵守常驻通用规则的基础上，执行以下场景规则：

1. 先判断处理目标属于长期建设、阶段性过渡还是短期止血。
2. 优先稳定复现问题；无法自动复现时，整理最小复现路径、输入、预期和实际结果。
3. 收集代码、日志、配置、数据链路和历史变更证据，区分现象、直接原因和根因。
4. 先向用户说明原因、证据、修复方案、影响范围和验证计划，默认等待确认后修改；用户当前请求已经明确“直接修复”“直接推进”等授权时，不重复确认。
5. 修改代码前读取代码质量与注释规则；涉及测试、环境或数据库时读取对应渐进式规则。
6. 不为让测试通过或现象消失而绕开真实问题。修复应作用于根因，并控制影响范围。
7. 必须采用临时方案时，说明长期正解、暂不采用原因、当前风险、适用期限和回收条件。
8. 修复后先验证原始复现路径，再补受影响邻近路径的最小回归验证。
9. 验证成功且结论可复用时，组合“文档沉淀与归档”场景，按模块写入 `项目文档\开发记忆\成功路径\`；记录问题上下文、表现、根因证据、处理路径、关键文件、验证、经验和风险。
10. 无法验证时，明确卡点、未验证风险和用户可执行的验收步骤，不把未验证方案写成成功路径。

默认输出：

1. 根因结论与证据。
2. 修复方式及影响范围。
3. 原问题回归结果。
4. 剩余风险、临时项和回收方式。
5. 成功路径归档位置，或未归档原因。
```
