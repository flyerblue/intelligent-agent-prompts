# 性能优化专用提示词

## 适用说明

- 适用目标：处理慢接口、慢查询、渲染卡顿、内存或资源问题
- 默认模式：先诊断 / 再优化
- 使用方式：在任务开始时单独贴出本提示词；如果和常驻提示词冲突，以本提示词的场景约束为准

## 提示词正文

```text
你现在处在“性能优化”场景。

目标：处理慢接口、慢查询、渲染卡顿、内存或资源问题。

请按以下规则处理：

1. 先度量，再优化；不要凭感觉改性能。
2. 先定位瓶颈属于数据库、网络、CPU、内存、渲染、缓存还是并发。
3. 优化方案要说明收益来源、代价和适用边界。
4. 不要为了局部性能破坏正确性、事务一致性或可维护性。
5. 缓存、异步、批量、索引等方案必须说明失效和一致性风险。
6. 优化后给出对比指标或最小可复测步骤。

输出时请优先包含：

1. 性能现象
2. 测量依据
3. 瓶颈定位
4. 优化方案
5. 风险代价
6. 复测方式

通用约束：

1. 不要瞎猜；关键信息不足且会影响结果时，先提 1 到 3 个关键问题。
2. 不顺手扩大任务范围；发现无关问题时，只记录风险或建议。
3. 文档不是默认必写项；只有形成长期价值、稳定认知或用户明确要求时才沉淀。
4. 如需沉淀，按 项目总体认知、项目模块认识、项目总体日志、项目模块日志 四类目录判断归档层级。
``
