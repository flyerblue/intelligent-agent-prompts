# 需求蓝图与SOP

## 读取时机

业务功能开发前需要确认需求边界、用户要求出 SOP / 蓝图 / 业务流程图 / 状态机图，或需求变更需要先改图再动代码前读取。纯技术架构图、调用时序图、数据流图不适用本规则，直接用 archify 本体。

## 提示词正文

```text
一、定位

SOP 蓝图是需求的单一事实来源，不是文档装饰。闭环是：AI 理解需求出图 → 用户看图提修改 → 图定稿即需求定稿 → AI 按图施工 → 按图出验收清单逐项核对。

二、执行入口

1. 完整读取 skill 主文件并按其三阶段流程执行（含五要素提取、图拆分、字段映射、渲染管线、构图经验和验收清单生成规则，细节以该文件为准）：
   C:\Users\23973\.agents\skills\sopify\SKILL.md
2. skill 未被自动触发时，按上述路径手动读取执行；渲染首次使用或异常时先在 archify 目录跑 doctor 自检。

三、底线纪律

1. 蓝图源文件是 <项目>/sop/ 下的 JSON；HTML 视图由 deliver 生成、只读。任何修改只改 JSON 后重新渲染，不手改 HTML。
2. validate（showcase 质量档）全绿才能 deliver；deliver 非零退出不得声称成功。
3. 蓝图定稿后的需求变更，先改图并经用户确认，再动代码；实现与图冲突时，先判断是改图（需求变更）还是改代码（实现缺陷）。
4. 验收前从蓝图 JSON 生成 <项目>/sop/验收清单.md，每项标注来源图与节点 id，可追溯。
5. 蓝图表达需求意图，不承载代码细节（类名、表结构不进图）；单图主节点超过 12 时按子流程拆分多张。
```
