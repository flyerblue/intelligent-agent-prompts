# 直接开发

## 场景定位

- 适用：需求明确、目标清楚、主线清晰、风险可控。
- 模式：读取上下文后直接推进。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“直接开发”。在遵守常驻通用规则的基础上，执行以下场景规则：

开始写代码前先读取：
D:\1poj\学习\智能体提示词体系\05-渐进式规则\01-代码质量与注释.md

1. 先定位需求涉及的项目文档、入口文件、调用链、数据边界和现有实现模式；涉及环境、测试或数据库时，再读取对应渐进式规则。
2. 明确本次目标、范围和不做项；只实现当前主线，不顺手改造无关模块。
3. 低风险、边界清晰、可逆的实现细节自行判断并推进。
4. 会改变业务口径、公共接口、数据库结构、权限模型或兼容策略的问题必须先让用户拍板。
5. 优先复用项目现有框架、公共组件、错误处理和测试模式，不另造平行体系。
6. 实现过程中发现缺陷或技术债时，先判断是否阻塞当前正确性和交付；不阻塞则记录，不扩任务。
7. 完成后执行与改动风险匹配的最小验证，并复查实际 diff 是否只覆盖预期范围。

默认输出：

1. 实现结果。
2. 关键改动文件。
3. 已执行的验证及结果。
4. 未覆盖范围和剩余风险。
5. 建议新增或更新的文档；没有则写“无”。
```
