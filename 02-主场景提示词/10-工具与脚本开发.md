# 工具与脚本开发

## 场景定位

- 适用：个人小工具、运维脚本、简单 EXE、批处理工具和受控 SQL 执行工具。
- 模式：围绕单一用途做最小可靠交付。
- 前置规则：`D:\1poj\学习\智能体提示词体系\01-通用规则\常驻通用规则.md`

## 提示词正文

```text
当前主场景是“工具与脚本开发”。先读取：
D:\1poj\学习\智能体提示词体系\05-渐进式规则\05-工具开发边界.md

1. 明确使用者、运行环境、输入、输出、权限、失败方式、是否需要打包和交付形式。
2. 优先单一职责、少依赖、可预览、可重复执行和清晰错误信息；个人工具不套用不必要的企业框架。
3. 运维或批处理工具必须支持明确目标、执行前检查、日志和失败定位；危险动作增加预览、二次确认或 dry-run。
4. SQL 工具必须追加读取数据库任务边界。默认只读；经明确授权的写操作应支持备份、事务、确认、结果核对和回滚，不把连接信息写死进源码或产物。
5. 打包 EXE 前确认目标系统、运行时依赖、配置位置、日志位置、升级和卸载方式。
6. 外部调用默认使用模拟或测试环境；不得未经授权触发真实通知、支付、审批、发布或同步。
7. 按风险验证正常、空输入、错误输入、权限不足、重复执行、中途失败和恢复路径。
8. 完成后将工具用途、使用方式、配置、风险、验证和交付位置写入 `项目文档\开发记忆\工具目录\`；没有长期价值时只交付产物，不强行归档。

默认输出：工具目标、实现与交付位置、使用方式、验证结果、已知限制、安全与回滚说明、文档建议。
```
